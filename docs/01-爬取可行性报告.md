# 爬取可行性测试报告（杭州试点）

测试时间：2026 年（本次会话）
测试目标：判断"出去玩地点选择转盘"所需的**地点数据（含高德可点击链接）**与**评价内容**能否从各站点稳定获取。
测试范围：杭州市（火锅/餐饮、景点、娱乐等关键词），仅验证可行性，不做全量抓取。

原始证据目录：`tests/out/`（每个站点的响应体、报告文本均已落盘，可复核）
探测脚本：`tests/probe-sites.ps1`（首轮）、`tests/probe-apis.mjs`（JSON 接口）、`tests/probe-round2.mjs`（HTML 源 + 高德接口挖掘）、`tests/probe-round3.mjs`（高德链接形态 + 官方 API）、`tests/probe-round4-browser.mjs`（真实 Chrome 渲染）

---

## 一、核心结论（一句话版）

**高德网页版已对未登录请求全面封堵，官方 Web 服务 API 畅通且必须自备 Key；小红书/大众点评/携程/马蜂窝/去哪儿在无人值守下均不可爬（滑块验证、登录墙、JS 挑战、空壳页）。**
因此推荐路线是：**高德开放平台官方 API 作为地点主数据源（自带 poiid，可直接生成"点开即跳高德"的链接）+ B 站 API 作为评价内容源 + 携程移动端静态 HTML 作为景点补充**，其余平台放弃自动化采集、改用"人工粘贴链接"或"分享导入"方式补充。

## 二、逐站点实测结果

### 2.1 地图类（地点数据 + 高德链接）

| 目标 | 实测结果 | 判定 |
|---|---|---|
| 高德网页版内部接口 `www.amap.com/service/poiInfo` | 200，但返回 **84,918 字节的 SPA HTML 外壳**，不是 JSON（`r2_amap_poiInfo_basic.txt`） | ❌ 接口已下线/需签名 |
| 高德网页版 `/typingSearch`、`/service/place/around` | 返回 `{"status":"8","data":"404 Not found!"}` | ❌ 已下线 |
| 高德搜索页（真实 Chrome 渲染） | 重定向到 `www.amap.com/ssr/search?...`，页面只有地图底图 + **"请按住滑块，拖动到最右边"登录框**，无 POI 列表（`r4_amap_search_hotpot.txt`，正文仅 283 字节） | ❌ 未登录拿不到结果 |
| 高德 `/detail/get/detail`、`/place/{poiid}` 页 | 返回同一 SPA 外壳，无数据 | ❌ |
| Bing 索引 `site:amap.com/place` 挖 poiid | 提取到 **0 个** poiid | ❌ 搜索引擎旁路无效 |
| 移动端 `m.amap.com` 搜索页 | 715,529 字节，是 App 下载引导页，非数据页 | ❌ |
| **高德开放平台 Web 服务 API**（`restapi.amap.com/v3|v5`） | 5 个接口全部 HTTP 200，返回标准错误 `{"status":"0","info":"INVALID_USER_KEY","infocode":"10001"}` —— **接口通畅，仅缺 Key**（`r3_rest_B1..B5.txt`） | ✅ **可行（需自备 Key）** |
| 百度地图 `map.baidu.com/?qt=s` | 200，返回 `{"content":[[]],"result":{"anti_session":{"need_recaptcha":true}}}` —— 直接要求验证码 | ❌ 反爬拦截 |
| 腾讯位置服务 API | 需 Key，未测（同高德模式，仅作备份） | ⚠️ 备份 |
| OpenStreetMap Overpass API | ✅ 可用，成功返回杭州餐厅 node（含 `name`、`lat`、`lon`、`amenity`）`r3_osm_D2.txt`；但**无中文商户质量、无评分、无高德链接、国内覆盖稀疏** | ⚠️ 仅作兜底/坐标补全 |

**高德链接形态（已逐一验证，HTTP 200 且跳转正确，`r3_link_A1..A5.txt`）：**

| 形态 | 链接模板 | 实测跳转 | 适用 |
|---|---|---|---|
| POI 详情页（最优） | `https://www.amap.com/place/{poiid}` | 200 | 有 poiid 时，点开就是该店页面 |
| URI 搜索（最稳，不依赖 poiid） | `https://uri.amap.com/search?keyword={店名}&city={城市}&view=map&callnative=0` | → `ditu.amap.com/search?query=火锅&city=杭州...` | 兜底方案，任何条目都能生成 |
| URI 标记点（手机可唤起 App） | `https://uri.amap.com/marker?position={lng},{lat}&name={店名}&coordinate=gaode&callnative=1` | → `ditu.amap.com/regeo?lng=...&lat=...` | 一键导航 |
| URI 导航 | `https://uri.amap.com/navigation?to={lng},{lat},{名称}&mode=car&policy=1` | → `ditu.amap.com/dir?type=car...` | 抽中后直接出发 |

> 结论：**"点击链接浏览器打开跳转高德"这一需求 100% 可实现**，且不依赖 Key（Key 只影响 poiid 质量）。

## 三、可爬取性总评

| 站点 | 免 Key 直连 | 真实浏览器 | 稳定性 | 建议用途 |
|---|---|---|---|---|
| 高德开放平台 API | ❌ 需 Key | — | ⭐⭐⭐⭐⭐ 官方稳定 | **地点主数据源（poiid/坐标/评分/电话/图片）** |
| 高德链接（URI/place） | ✅ | ✅ | ⭐⭐⭐⭐⭐ | **跳转链接生成** |
| B 站 | ✅ | ✅ | ⭐⭐⭐⭐ | 评价/推荐内容、热度排序 |
| 携程移动端 | ⚠️ 部分 | ⚠️ 有验证 | ⭐⭐⭐ | 景点榜单补充 |
| OSM Overpass | ✅ | ✅ | ⭐⭐⭐ | 无 Key 兜底、坐标补全 |
| 小红书 | ❌ | ❌ 登录墙 | ⭐ | 放弃自动采集；改为"粘贴分享链接"人工导入 |
| 大众点评 / 美团 | ❌ | ❌ 滑块 | ⭐ | 放弃 |
| 马蜂窝 / 去哪儿 / 同程 / 途牛 | ❌ | ❌ | ⭐ | 放弃 |
| 抖音 / 知乎 / 百度地图 | ❌ | ❌ | ⭐ | 放弃 |

**关键洞察：越是"高价值评价"的站点反爬越强（小红书/点评/美团），越是"结构化地点"的官方 API 越好用（高德）。所以产品重心应放在高德 API + B 站内容，而不是硬啃小红书。**

## 四、合规与风险提示（必须写清）

1. 《数据安全法》《个人信息保护法》与《反不正当竞争法》：绕过技术措施抓取 UGC 平台数据存在法律与封号风险；本项目**默认不采集受限平台**。
2. 高德开放平台服务条款：Key 绑定应用，**免费配额不可转售**；服务条款限制超出许可范围的使用（[高德开放平台服务升级/价格](https://developer.amap.com/upgrade#price#1)、[个人/企业开发者区别](https://developer.amap.com/faq/account/certification/39670)）。个人开发者配额 2021 年起由 300 万/日下调至 30 万/日量级，个人认证即可申请，次日零点重置（[相关说明](https://zhuanlan.zhihu.com/p/2060414698458177963)）。
3. 正确姿势：**官方 API 为主 + 遵守 robots.txt + 限速 + 本地缓存、不重复请求**；对不许爬的站点，产品上用"打开原站搜索"外链代替抓取。
4. 抓到的评价内容只做**个人使用/本地展示**，不二次分发。

## 五、已验证可用的落地契约（可直接开发）

### 5.1 高德官方 API（已确认接口存在，需用户提供 Key）

```
# 关键字搜索（v5，最新最全，返回 rating/photos/business）
GET https://restapi.amap.com/v5/place/text
    ?key={KEY}&keywords=火锅&region=杭州&city_limit=true
    &page_size=25&page_num=1
    &show_fields=business,photos,rating,cost,navi

# 周边搜索（按坐标，适合"3 公里内随机"）
GET https://restapi.amap.com/v5/place/around
    ?key={KEY}&location=120.1551,30.2741&radius=5000&types=050000&page_size=25

# 行政区划（省市联动下拉、随机城市）
GET https://restapi.amap.com/v3/config/district?key={KEY}&keywords=杭州&subdistrict=1&extensions=base
```

POI 关键字段：`id`（→ 生成 place 链接）、`name`、`address`、`location`(lng,lat)、`type`（→ 映射到"项目"分类）、`rating`、`cost`、`photos`、`tel`、`business.opentime`。

### 5.2 无需 Key 的兜底方案

- 链接生成：`uri.amap.com/search`、`uri.amap.com/marker`、`uri.amap.com/navigation`（已验证）
- 内容源：B 站搜索/评论 API
- 坐标兜底：OSM Overpass API（已验证返回杭州餐厅数据）

## 六、申请高德 Key 的操作步骤（需要用户执行，约 3 分钟）

1. 打开 [高德开放平台控制台](https://console.amap.com/dev/id/phone)，手机号注册/登录并完成**个人开发者认证**（需实名）。
2. 「应用管理 → 创建新应用」→ 添加 Key，**服务平台选「Web 服务」**（后端调用 REST API 必须选这个；不要选 Web 端 JS API）。
3. 复制 Key，写入项目根目录 `.env` 的 `AMAP_KEY=xxx`（本项目已预留读取逻辑）。
4. 免费配额足够杭州试点（数十个关键词 × 分页，量级在数百次/天以内）。

## 七、最终推荐的数据获取矩阵

```
地点主数据（景区/饭店/酒吧/KTV/麻将馆/爬山/影院/咖啡馆/密室/SPA…）
   └─ 高德开放平台 v5/place/text + v5/place/around   【需 Key，官方合规】
        └─ 产出：名称 / 地址 / 坐标 / 评分 / 人均 / 分类 / poiid / 高德链接

评价与"值得去"的理由
   ├─ B 站搜索 API（标题+播放量+UP 主）              【免 Key，已验证】
   ├─ 携程移动端静态页（景点榜单/评分）              【免 Key，部分可用】
   └─ 用户手动粘贴小红书/点评分享链接                【人工，零风险】

兜底
   ├─ OSM Overpass（无 Key 场景）                    【已验证】
   └─ 内置精选种子数据（杭州 6 大类 × 每类 15+ 条）  【离线可用，见 data/seed-hangzhou.json】
```
