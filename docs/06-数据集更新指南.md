## 0. 先回答最容易踩的那个问题

**只更新数据集，两个线上地址都会自动变新吗？**

| 线上地址 | 更新机制 | 只 push 够不够 |
|---|---|---|
| `https://2647199274-dotcom.github.io/places-choice/` | GitHub Actions（`.github/workflows/deploy.yml`）监听 `push main`，用仓库里的快照重新构建发布 | ✅ **够**，自动更新 |
| `https://places-choice.pages.dev` | Cloudflare Pages **命令行直传**（`wrangler pages deploy`），**没接 Git** | ❌ **不够**，必须再跑一条 `npm run deploy:cf-pages` |

已核实：`wrangler pages project list` 显示该项目的 `Git Provider: No`。
所以**默认情况下 Cloudflare 那份会停留在旧数据**，除非你手动再推一次（或者去接自动化，见第 5 节）。

> 一句话记法：**`github.io` 跟 push 走；`pages.dev` 要单独点一枪。**

### 三个常见误解（都被实际问过）

**误解 1：「我更新了数据库，用户就能看到新数据了。」**

不对。`data/trip.db` 只在你本机，用户永远看不到它。用户看到的是**发布到线上的静态快照**。完整链路：

```
data/trip.db（本地，仅你可写）
  → npm run export:static
web/public/data/dataset.json（提交进仓库的静态快照）
  → git push（github.io 自动发布） + npm run deploy:cf-pages（pages.dev 手动发布）
两个托管平台
  → 用户浏览器拉 data/dataset.json
```

**改库 ≠ 上线**，中间少了「导出 + 提交 + 发布」。只改库，线上毫无变化。

**误解 2：「链接会变，得重新发给用户。」**

不会。两个地址都是固定域名，更新数据不影响它们。用户**不用换链接、不用重新"添加到主屏幕"**，
已装的 PWA 照常工作（同一 origin）。

**误解 3：「用户刷新一下就能看到新数据。」**

不一定。Service Worker 对 `data/dataset.json` 用的是 **stale-while-revalidate**：
**第一次打开返回旧数据（同时后台下载新的），第二次打开才是新的**。
如果用户一直把 PWA 挂在后台、不重开页面，则根本不会重新拉数据。
想立刻看到新数据：连开两次 / 强制刷新（清缓存）。

## 1. 最短路径（数据更新全流程）

```powershell
cd "E:\direction chose"

# ① 采集新数据（需要外网 + .env 里的 AMAP_KEY；先 --plan 看规模，别一次打爆配额）
npm run collect -- --scope china --province 广东省 --all --pages 2

# ② 去重（种子数据与采集数据同名同城的会标 seed-dup）
npm run dedupe

# ③ 导出静态快照 —— **必须在有 data/trip.db 的机器上跑**（关键，见第 3 节陷阱 1）
npm run export:static

# ④ 校验 + 跑全套测试（会拦住"快照退化成种子数据"这类事故）
npm test

# ⑤ 看数据现状（条数 / 覆盖率 / 快照时间，用来写提交信息）
node tests/status-report.mjs

# ⑥ 存档并推送（这一步会让 GitHub Pages 自动重新发布）
git add -A
git commit -m "data: 扩广东省数据（XX 城 / XX 条）"
git push origin main

# ⑦ 更新 Cloudflare Pages（手动，不能省）
npm run deploy:cf-pages

# ⑧ 两个线上地址都做端到端验证
npm run test:live
npm run test:live -- https://2647199274-dotcom.github.io/places-choice/
```

两条 `test:live` 都必须 exit 0 才算发布完成。

## 2. "我改了什么 → 我该跑什么"对照表

| 改动 | 必跑 | 部署 |
|---|---|---|
| 只加/改采集数据（`data/trip.db` 变了） | `dedupe` → `export:static` → `npm test` | push + `deploy:cf-pages` |
| 手工修几条数据 | 同上（**不要直接改 `dataset.json`**，它是生成物，下次导出会被覆盖） | 同上 |
| 改前端代码（`web/`） | `npm test` + `npm run test:web`（真实 Chrome） | push + `deploy:cf-pages` |
| 改抽签规则（`src/core/draw.ts` 或 `web/src/localDraw.ts`） | **必须两端同步改**，再跑 `npm test` + `npm run test:local`（逐字段对拍） | 同上 |
| 改分类口径（`config/categories.json`） | 重新采集该分类 → `export:static` → `npm test` | 同上 |
| 改部署配置（`.github/workflows`、`wrangler.jsonc`） | `npm test`；改完 push 后看 Actions 与 CF 部署日志 | 按改动而定 |
| 只改文档（`docs/`） | `npm run typecheck`（走一遍门槛即可） | push（`github.io` 会重建；`pages.dev` 不必重推） |

## 3. 陷阱清单（按踩坑代价排序）

### 1) `npm run export:static` 必须在有真实数据库的机器上跑

`data/*.db` 是 **gitignore** 的。在 CI、新 clone、或删过 `data/` 的机器上，
`openDb()` 会**新建一个空数据库**（不是返回 null），`ensureSeeded()` 灌进 647 条种子数据，
导出脚本会把"空库 + 种子"当成真实数据 —— 本项目已经因此把线上数据从 25820 条静默搞成 671 条过一次。

**现在有两道保险**：
- `export:static` 内置"拒绝把大快照覆盖成更小"的安全阀（要强推得加 `--force`）；
- `npm test` 里的 `verify:dataset` 会断言地点数下限 20000、与 `meta.json` 一致。

**但根子上还是靠这条**：导出前先 `node tests/status-report.mjs` 确认总数是两万多条，不是几百条。

### 2) ⚠️ 真实数据只存在 `data/trip.db` 里，而且不备份就会很贵

| 文件 | 体积 | 是否进仓库 |
|---|---|---|
| `data/trip.db` | **27.6 MB** | ❌ 被 gitignore（**唯一可写的真实数据源**） |
| `data/trip.db-wal` | 4.2 MB | ❌ 被 gitignore（未合并的事务，**必须跟 db 一起备份**） |
| `data/seed-hangzhou.json` | 0.7 MB | ✅ 已提交（只是种子数据） |
| `web/public/data/dataset.json` | 6.4 MB | ✅ 已提交（导出快照，可读但**无法反导回数据库**） |

**结论：丢了 `data/trip.db` 就只能重新采集，等于再烧一遍高德配额。**
建议定期把 `data/trip.db` + `data/trip.db-wal`（两者要一起，或用 `-shm` 也行）复制到别处存档。
现在没有任何脚本能把快照反导回 SQLite（`scripts/` 里只有导出方向），这是已知缺口。

### 3) 高德配额要分批花

全国 392 城全量约 **6.3 万次请求**，远超免费日配额。**按省分批**：

```powershell
npm run collect -- --scope china --plan                        # 先看规模，不发请求
npm run collect -- --scope china --province 广东省 --all --pages 2
```

采集口径由 `config/categories.json` 的 `amapTypes`/`keywords` 决定（27 分类 × 每城关键词 × 页数）。

### 4) 快照体积要盯着

单文件上限：Cloudflare Pages / Workers 静态资源都是 **25 MB**。现在 6.4 MB，还很宽裕，
但按省扩到全国后要留意。超过就得分片或换存储（届时前端 `api.ts` 的取数逻辑要一起改）。

### 5) 用户手机上可能"看起来没更新"

Service Worker 对 `data/dataset.json` 用的是 **stale-while-revalidate**：
**先给旧数据、后台悄悄下新的**。所以更新后用户第一次打开可能仍是旧数据，**第二次打开才是新的**。
App Shell（HTML/JS/CSS）是 cache-first 且 `sw.js` 里的 `VERSION` 没变就不更新 —— 一般不用管，
要强制刷新就改 `web/public/sw.js` 的 `VERSION` 常量。

### 6) 新增城市不会立刻显示

邻近城市 POI 泄漏会带来"只有 1～2 条"的城市。界面有 **5 条**阈值，低于它不展示（数据保留）。
所以扩数据后如果某城市"采集到了但界面没有"，先看它是不是条数太少。

### 7) 环境相关的坑（详见交接稿第 2、6 节）

- 受限沙箱下 `vite build` / 启动 Chrome / `git push` 会分别报 `spawn EPERM` 与
  `SEC_E_NO_CREDENTIALS`，需要提权一次重试（这是沙箱限制，不是项目坏了）；
- `.env` 里的 `AMAP_KEY` **绝不能提交**（已在 .gitignore）；
- Powershell 5.1 不支持 heredoc 与 `??`。

## 4. 发布后必须做的验证

```powershell
npm run test:live                                                    # pages.dev
npm run test:live -- https://2647199274-dotcom.github.io/places-choice/   # github.io
```

`tests/check-live.mjs` 会开真实 Chrome、**全新 context 模拟第一次访问**，检查：

- `/api/dataset` 必须 **404**（前端靠它判断"没有后端"；若返回 200 + HTML 会静默崩）；
- `/data/meta.json` 的地点数与期望一致（默认 25820，可用 `EXPECT_PLACES` 覆盖）；
- 界面徽标是 `X 市 · Y 个地点`，数据来源标识是 **`📦 静态数据`**（不是 `🌐 在线`）；
- 不出现"连不上后端"错误；控制台无真报错（`/api/*` 的 404/405 属静态部署正常现象，已单独归类）；
- **真的转一次**，确认本地抽签引擎可用；并截图到 `tests/out/live-*.png`。

> **为什么不能只跑本地 `npm run test:web`**：本地静态服务器会老老实实对未命中路径返回 404，
> 而 Cloudflare Pages 在没有顶层 `404.html` 时会回落成 `200 + index.html`。
> 这类"只在部署环境出现"的问题只有 `test:live` 抓得到（本项目已实际踩过一次）。

## 5. 想让"一次 push 同时更新两个地址"（可选）

现状是 CF 那份要手动推。两种自动化方案：

### 方案 A：GitHub Actions 直传（改动最小，推荐）

加一个工作流，用 `wrangler pages deploy` 把构建产物推到 Pages。需要：

1. 在 Cloudflare 建一个 API Token（权限 `Cloudflare Pages: Edit`）；
2. 存到仓库密钥：GitHub → `Settings` → `Secrets and variables` → `Actions` → `New repository secret`，
   名字 `CLOUDFLARE_API_TOKEN`，值粘贴 token；
3. 再加一个 `CLOUDFLARE_ACCOUNT_ID`（值 `dd85f9b8456bedaf1c6164d595ebf623`）。

之后 push 一次，两处同时发布。

### 方案 B：控制台 Git 集成

Cloudflare 控制台 → `Workers & Pages` → 新建 **Pages** 项目并连 GitHub 仓库（当前这个项目是直传项目，
接不了；要新建一个）。构建配置：

| 字段 | 值 |
|---|---|
| Framework preset | `None` |
| Build command | `node scripts/verify-static-dataset.mjs && npm run build:web` |
| Build output directory | `web/dist` |
| 环境变量 | `NODE_VERSION=22`，**不要**设 `VITE_BASE` |

代价：多一个项目、域名会变（`<新名字>.pages.dev`），要重新"添加到主屏幕"。
