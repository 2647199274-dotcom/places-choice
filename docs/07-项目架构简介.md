# 项目架构简介（给你看的）

> 一句话：**这是一个离线优先的、数据驱动的决策类 Web 应用**，
> 用真实 POI 数据把一个"去哪玩"的决策过程压缩成一次转盘交互。
> 线上：https://places-choice.pages.dev ｜ https://2647199274-dotcom.github.io/places-choice/

---

## 一、整体形态

它不是一个"网页"，而是一套**同源构建、多端分发**的静态应用：同一份 Vite 产物，
既能挂在 GitHub Pages 子路径、也能挂在 Cloudflare 边缘节点，还能被 Capacitor 原样封装成 Android APK。
运行时不依赖任何常驻服务端 —— 这是刻意的架构选择：**把复杂度留在构建期，把可用性留给运行时。**

## 二、分层架构

```
采集层   amap.ts（高德 v3 Place API）+ districts.ts（全国省市区划）
          ↓ 幂等 upsert（sanitizeForDb + 来源标记 source/amap|seed|seed-dup）
持久层   SQLite（data/trip.db）+ 仓储封装 + ensureSeeded 种子补灌与陈旧行清理
          ↓
领域层   draw.ts（抽签权重/冷却/过滤/吃饭规则）· areas.ts（区域四维聚合与交集）
          ↓
交付层   ① Fastify API（/api/dataset、/api/draw、/api/areas）+ 静态托管
         ② 构建期导出的静态快照 dataset.json（离线部署用）
          ↓
客户端   React SPA + PWA：IndexedDB 持久化 · Service Worker · 本地抽签引擎
```

**关键点：交付层是双通道的**（在线走后端、离线走静态快照），
所以领域层必须做到**契约一致性** —— 后端引擎与前端本地引擎用同一随机源注入后**逐字段对拍**
（`npm run test:local`），否则会出现"离线结果和在线不一样"这种最难查的 bug。

## 三、数据资产

26 省 / 53 城 / **26194 条** POI（含高德真实评分 99%、人均 71%、商圈 71%、poiid 100%、精确坐标 100%），
27 个分类；导出为 **6.55 MB** 的精简快照（字段名压缩，体积约为完整格式的 1/4），
随仓库版本化发布 —— 也就是说**数据即代码，可回溯、可审计、可 diff**。

## 四、离线优先（Offline-first）

- **持久化**：全量数据集写 IndexedDB（localStorage 容量不够，曾因此静默失败）；
  足迹/历史这类小数据仍走 localStorage。
- **缓存策略**：App Shell（HTML/JS/CSS/图标）用 cache-first；
  `data/*.json` 用 **stale-while-revalidate**（先给旧的、后台静默拉新）。
- **能力降级**：网络不可达时自动切换到本地抽签引擎，转盘、结果卡、跳高德、足迹记录全部照常可用，
  只在顶部徽标提示数据来源（`🌐 在线` / `📦 静态数据` / `📴 离线`）。

## 五、部署拓扑

| 目标 | 路径语义 | 更新方式 |
|---|---|---|
| GitHub Pages | 子路径 `/places-choice/`（`VITE_BASE`） | push 触发 GitHub Actions 自动构建发布 |
| Cloudflare Pages | 根路径（不设 `VITE_BASE`） | `npm run deploy:cf-pages` 命令行直传 |
| Android APK | 本地文件协议 + 可配置 `VITE_API_BASE` | Capacitor 打包（待办） |

同一份源码在两个平台用**不同的 base 语义**部署，Service Worker 用 `new URL('./')` 自适应作用域 ——
这是"一份产物挂多个域名"的代价与解法。

## 六、质量门禁

七套自动化验证：类型检查、抽签引擎（6000 次空转卡方检验落点分布）、多城市查询边界、
全国区划归一化、区域四维交集、采集器 mock、静态快照规模与一致性。
另有**线上端到端检查**（`npm run test:live`）：真实 Chrome 以全新会话模拟首次访问，
校验数据完整性、404 语义、控制台健康度，并实际抽一次签。

这套门禁不是形式主义 —— 它拦下过三类"静默故障"：
线上数据被种子数据覆盖（25820 → 671 条）、CI 空数据库导出、以及静态托管把 404 回落成 200 导致前端误判在线。
**它们的共同特征是：界面看起来正常，数据却是错的。**
