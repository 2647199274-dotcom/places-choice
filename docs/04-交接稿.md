## 0. 一句话说清这是什么

一个"出去玩去哪"的决策工具：选地区 + 选项目 → 转盘转一下 → 落到哪家就去哪家，结果卡一点直接跳高德看店/导航。
数据来自**高德开放平台官方 API**（真实 POI、真实评分、真实 poiid），支持**离线转盘**，网页可装到手机主屏幕当 App。

### 沙箱/环境坑（踩过，别重踩）

1. **`npm install` / `vite build` / 启动 Chrome 在受限沙箱下会 `spawn EPERM`** —— 需要提权重试一次（按规则：一次真实拒绝 → 原命令 + 提权 + 一句理由）。
2. **`web/dist` 的 base 路径**：Pages 必须 `VITE_BASE=/places-choice/` 构建；本地/APK 必须用**根路径**构建。
   同一份 dist 不能同时服务两者 —— 本地跑 `npm run api` 前先做一次根路径 `npm run build:web`。
3. **PowerShell 5.1**：不支持 heredoc（`<<`）与 `??`；写提交信息用临时文件 + `git commit -F`。
4. API 服务可能占着端口：改完代码要**重启** `npm run api` 才会生效（旧进程还在服务旧数据）。

## 4. 线上部署：两个地址，都已实测可用

| 地址 | 部署方式 | 更新方式 |
|---|---|---|
| **https://2647199274-dotcom.github.io/places-choice/** | GitHub Pages（`deploy.yml`） | `git push origin main` 自动构建发布 |
| **https://places-choice.pages.dev** | Cloudflare Pages（`npm run deploy:cf-pages`） | 手动跑一条命令（见 `docs/05-Cloudflare部署说明.md`） |

**为什么有两个**：`github.io` 在国内时通时不通（换运营商/换时间差异大），多一个 `pages.dev` 做备份。
实测：本机（国内网络）**两个都通**（首页/资源/数据全 200）。
⚠️ 已弃用：`places-choice.2647199274.workers.dev`（Cloudflare Worker）—— `workers.dev` **整段被 DNS 投毒**
（随机名字都解析到假 IP，含 Facebook 的段），国内打不开，见 `docs/05` 的实测数据表。

### 三条铁律（都踩过，别重踩）

1. **CI / 部署时不要重新导出数据集。** 线上直接用仓库里提交的 `web/public/data/dataset.json`。
   原因见第 6 节「CI 上重新导出数据集」——那条坑让线上静默少过 97% 的数据。
2. **必须有顶层 `404.html`（`web/public/404.html`）。** Cloudflare Pages 官方行为：没有它就把
   **所有未命中路径回落成 `200 + index.html`** → 前端 `/api/dataset` 拿到 200 HTML → 误判"在线"且没数据。
   它是功能性文件，`npm test` 里有断言盯着。
3. **GitHub Pages 要子路径 `/places-choice/`（设 `VITE_BASE`），Cloudflare Pages 要根路径（不要设）。**

### 上线后必须做的验证

```powershell
npm run test:live                                                    # 查 pages.dev
npm run test:live -- https://2647199274-dotcom.github.io/places-choice/   # 查 GitHub Pages
```

这条会开真实 Chrome 模拟"第一次访问"，检查快照完整性、数据来源标识、`/api/dataset` 是否 404、
控制台有没有真报错，并**真的转一次**。**本地的 `npm run test:web` 测不出上面第 2 条那种坑**
（本地静态服务器会老老实实返回 404），所以线上检查不能省。

> 手机端注意：若这台手机以前打开过旧版本，可能被 Service Worker 缓存住 → 用无痕窗口，或清除浏览器数据后再打开。
> 两个地址是**两个不同 origin**，缓存/足迹互不相通，建议只把其中一个"添加到主屏幕"。

## 6. 踩过的坑（血泪清单，改代码前扫一眼）

### 数据采集
| 坑 | 现象 | 现状 |
|---|---|---|
| 高德 v5 被截断 | 同查询 v5 只回 25 条，v3 回 600 条 | 已全部改用 **v3** |
| v3 分页语义 | `offset` 递增会**重复上一页** | 必须 **`page` 递增、`offset` 固定 0**（每页 10 条） |
| **直辖市 adcode** | `region=310100/500100/120100` **返回北京数据** | 直辖市改用城市名查询 + 自动回退（上海 87→1661 条） |
| 邻近城市 POI 泄漏 | `citylimit=true` 也挡不住，冒出 100+ 个"只有 1 条"的城市 | 按 adcode 前缀硬过滤；零星数据保留但 UI 不展示（阈值 5 条） |
| 区县 vs 城市 adcode | 高德返回的是区县级，按城市查全落空 | 库里有 `city_adcode`（查询键）+ `region_adcode`（区县） |
| 种子数据重复 | 同一家店两个扇区，种子那条只能"搜索" | `npm run dedupe` 标记 `seed-dup`（可回滚） |

### 代码/运行时
| 坑 | 现象 | 现状 |
|---|---|---|
| 迁移顺序错误 | 索引建在缺列的旧表上 → 迁移失败 → **静默降级 JSON，采集数据被丢弃** | `upsertPlaces` 库不可用直接抛错；采集前 `requireDb()` |
| SQLite bind 清洗 | undefined/对象字段让整个写库崩 | 已加 `sanitizeForDb()`；**新增字段记得一起清洗** |
| SQL 占位符 | `OR xxx IN (?)` 复用参数 → `RangeError: Too few parameter values` | 每个 `IN (...)` 各占一份；已有空数组/单城/多城边界测试 |
| **Service Worker 兜底** | 把 `/api/*` 的 404 用 `index.html` 响应 → 前端拿到 HTML 误判"在线" | SW 里 `/api/*` 完全直连网络；静态资源**绝不用 HTML 替换** |
| localStorage 装不下 | 2.8MB 数据集写不进 → 数据只在内存 → 关页面离线打开就没数据 | 数据集改 **IndexedDB**（足迹仍用 localStorage），并有持久化断言 |
| 省份写死浙江 | 全国化后广东显示"其他"，"全省随机"永远只抽浙江 | 省份映射读 `region` 表 level=1（34 省）+ 省份选择器 + `provinceAdcode` |
| 前后端双引擎 | 离线引擎与后端规则不一致会让"离线结果跟在线不一样" | 改任一侧必须同步另一侧 + 跑 `npm run test:local`（逐字段比对） |
| **CI 上重新导出数据集** | CI 没有 `data/*.db`（被 gitignore），`openDb()` 会**新建空库**而不是返回 null → `fromSeed()` 兜底根本不触发，导出脚本把"空库 + 647 条种子"当成 `source: 'sqlite'` 的**真实数据**，**覆盖掉仓库里 25820 条的快照**；线上只剩 671 条 / 11 城，界面看不出异常（静默数据丢失） | CI 里**已删掉导出步骤**（线上只用仓库里提交的快照）；新增 `npm run verify:dataset` 断言下限 20000 条；导出脚本加"拒绝把大快照覆盖成更小"的安全阀 |
| **静态托管把 404 回落成 200** | Cloudflare Pages 在没有顶层 `404.html` 时按单页应用处理，未命中路径返回 **200 + index.html**；前端 `res.json().catch(()=>null)` 不抛错 → `App.tsx` 访问 `d.generatedAt` 抛 TypeError → **首次访客只看到"连不上后端"** | 已加 `web/public/404.html`（功能性文件）+ `verify:dataset` 断言；本地 `test:web` 测不出，**上线必跑 `npm run test:live`** |
| **真实数据只在未跟踪的 `data/trip.db` 里** | `data/*.db` 被 gitignore（27.6MB + 4.2MB 的 `-wal`），而它是**唯一可写数据源**；快照 `dataset.json` 只能读、**没有反导脚本**。丢了就得重新采集（再烧一遍高德配额） | 见 `docs/06` 第 3 节；**建议定期把 `trip.db` 和 `trip.db-wal` 一起备份到仓库外** |
