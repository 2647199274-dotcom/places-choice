# 转盘抽签规则契约

改规则 = 改契约。**前端 `web/src/localDraw.ts` 与后端 `src/core/draw.ts` 是两份实现，必须同步改**，
改完跑 `npm run test:local`（逐字段比对）与 `npm run test:draw`。

## 规则清单

| 规则 | 现状 | 位置 |
|---|---|---|
| **吃饭选项** | `required: false`（人工选择可取消）+ `alwaysInRandom: true`（随机模式必定包含） | `config/categories.json` |
| **项目权重** | `weight` 越大扇区越大；吃饭 3.0，火锅 1.6，冷门 0.7~1.0 | 同上 |
| **扇区数量** | 取候选池权重前 10（可传 `segmentCount`，上限 12）；不足 2 个时全取 | `draw.ts` |
| **扇区大小** | 权重占比，收敛到 `[4%, 32%]` 之间（避免针尖/巨扇区看不清） | `draw.ts` |
| **落点** | **加密均匀随机**（后端 `crypto.randomInt`、前端 `crypto.getRandomValues`）→ 落点公平，权重只影响扇区大小 | `draw.ts` / `localDraw.ts` |
| **候选新鲜度** | 从权重排序后的剩余池随机替换约 20% 扇区，避免每盘都是同几家 | `draw.ts` |
| **冷却** | 最近 5 次抽中的不再出现 | `filterPlacesByAreas` 之外的 `recentPlaceIds` |
| **过滤** | 排除已去过 / 人均上限 / 评分下限 | `filters` |
| **区域交集** | 地铁∩地区∩商圈∩商场，多选取交集 | `src/core/areas.ts` |
| **空池** | 返回 `null` → 前端提示换条件，绝不硬抽 | 两端一致 |

## 公平性怎么证明（别凭感觉）

`npm run test:draw` 会空转 6000 次做卡方检验：落点分布必须与扇区占比一致。
当前基线：卡方 ≈ 16.8（df ≈ 16），远低于宽松上界。**改完权重/收敛逻辑后重跑，看卡方有没有失控。**

## 不要做的事

- 不要为了"抽到更好的店"偷偷改落点分布（那是内定，用户明确要公平随机）
- 不要让 `required: true` 之类硬锁定回来（用户明确要求人工选择时可取消吃饭）
- 不要在随机模式下漏掉吃饭（`alwaysInRandom` 就是为这个存在的）
- 不要只改一端：两端不一致会让"离线转出来的结果"和在线不一样
