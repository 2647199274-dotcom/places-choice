# 数据源调研（本项目专用）

这是本项目从 `deep-research`（academic-research-skills，本地 `E:\小车生涯\轮腿\my claude skills`）裁剪而来的轻量版：
只保留"能不能采、怎么采、合规吗"这条主线，去掉论文/系统综述那套流程。
需要做真正深度的多智能体研究时，去用上游那份完整 skill。

## 铁律

1. **先实测，再下结论**。任何"某网站可以爬/不能爬"的说法都必须有本次会话的真实响应作为证据。
   证据落盘到 `tests/out/`，结论写进 `docs/01-爬取可行性报告.md`。
2. **必须给出 HTTP 状态码 + 响应体特征**（大小、是否 SPA 空壳、是否验证码/登录墙、JSON 还是 HTML）。
3. **该站点反爬越强，越要直接说"不做自动化采集"**，并给替代路径（官方 API / 静态页 / 人工粘贴链接）。
4. **合规优先**：只用官方 API 与许可允许的数据；绕过验证码、伪造签名、抓登录后数据一律不做。
5. 结论要能落到代码：要么产出采集器参数（接口 + 字段 + 分页），要么产出"放弃 + 替代"的明确决定。

## 标准流程

```
1. 摸接口   → curl/fetch 试探：网页、移动端、内部 XHR、官方 API
2. 判反爬   → 状态码 / 空壳页 / 滑块 / 登录墙 / JS 挑战 / 签名头
3. 验字段   → 真跑一次，确认字段是否齐全（名称/地址/坐标/评分/人均/分类/外链）
4. 试分页   → 单查询总量上限、分页参数语义（本项目踩过坑：v3 必须 page 递增、offset 固定 0）
5. 定结论   → 可采（写清接口与限速）/ 部分可采（写清边界）/ 不可采（给替代方案）
6. 落证据   → tests/probe-*.mjs 脚本 + tests/out/ 原始响应 + 报告更新
```

## 本项目已有的结论（别重复踩坑）

| 来源 | 结论 | 依据 |
|---|---|---|
| 高德官方 Web 服务 API | ✅ 主数据源，需 Key（`.env` 的 `AMAP_KEY`） | `docs/01-爬取可行性报告.md` |
| 高德网页版（www.amap.com） | ❌ 未登录即滑块登录墙，内部接口返回空壳 | 同上 |
| 小红书 / 大众点评 / 美团 / 马蜂窝 / 去哪儿 | ❌ 登录墙 + 滑块 + JS 挑战，不做自动化 | 同上 |
| B 站 API | ✅ 可用（评价内容源） | 同上 |
| 携程移动端静态页 | ⚠️ 部分可用 | 同上 |
| OSM Overpass | ⚠️ 无 Key 兜底（`overpass-api.de` 可用） | 同上 |

**高德 v3 分页坑（勿重犯）**：`page` 递增、`offset` 固定 0 才正确；`offset` 递增会重复上一页数据。
证据：`tests/probe-amap-paging.mjs`。
